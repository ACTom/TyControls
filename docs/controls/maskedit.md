# TTyMaskEdit

## 1. 概述

TTyMaskEdit 是**掩码编辑框**(日期 / 电话 / IP …),继承自 [TTyEdit](edit.md),复用它的文本引擎与 `'TyEdit'` 主题。**从左到右追加式录入**:每个键若匹配下一个可编辑槽就接受(自动补上字面量),否则拒绝;退格删除最后一个有效字符。显示的 `Text` 始终由有效字符经 `TyMaskApply` 推导——**没有独立模型需要同步**。`Mask=''` 时退化为普通编辑。

## 3. 掩码码

| 码 | 含义 |
|----|------|
| `#` | 数字 `0-9` |
| `L` | 字母 `A-Za-z` |
| `C` | 任意非空格字符 |
| 其它 | **字面量**(如 `/` `-` `(` `)` 空格),自动插入 |

例:`##/##/####`(日期)、`(###) ###-####`(电话)、`###.###.###.###`(IP)。

### 3.1 语言边界:这**不是** LCL/Delphi 的掩码语言

**只有上面三个槽位码**,其余字符一律是字面量。没有转义符、没有可选槽码、没有 `>` `<` 大小写强制、也没有 `mask;save;blank` 三段式 —— LCL/Delphi(`maskedit.pp`)有约 17 个码,本控件有 3 个。**实现那套语言是另一件事,不在本控件计划内。**

真正危险的不是"少了十几个码",而是**一条 Lazarus `EditMask` 字符串对本解析器完全合法、含义却完全不同**:`'000-0000'` 里没有 `#`,于是八个字符全成了字面量,整个字段**一个可编辑槽都没有,永远收不到任何输入**,而且不报错、不打日志、外观照常。

因此以下两类掩码现在会**直接抛 `ETyMaskError`**(不再静默):

| 拒绝条件 | 例子 | 为什么 |
|----------|------|--------|
| 非空掩码但**没有任何可编辑槽** | `'000-0000'` `'99/99/00'` `'AAA-aaa'` | 收不到输入的字段没有合理用途;要惰性字段请用 `Mask := ''`(普通编辑)或 `ReadOnly := True`。 |
| 掩码里含 `;` | `'##/##;1;_'` `'!90:00;1;_'` | `;` 是 LCL 的 `mask;save;blank` 分隔符,没别的用法。这类掩码可能**仍有真槽位**(`'##/##;1;_'` 会照收数字、把 `;1;_` 悄悄丢掉),所以必须按名字拦。 |

**故意不拦**:混在有效槽位里的 LCL 码。`'19##'` 是完全正当的年份掩码,`9` 在这里就是字面量;为了抓一个假想的移植错误而拒掉能用的掩码,代价比病还大。开头的 `!` 同理放行 —— 而且它不像 `;`,作为字面量是**会画出来**的(`'!##'` 显示成 `!12`),自己会暴露。

`Mask := ''` 永远合法,含义是"没有掩码 = 普通编辑"。

想先检查再赋值,用纯函数 `TyMaskRejectReason(AMask)`:返回 `''` 表示可用,否则返回拒绝原因(就是异常里那段话)。

## 4. 属性 / 方法

| 成员 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `Mask` | `string` | `''` | 掩码模板;运行期改变会清空当前内容。**流式保存的是这个名字。** 非法掩码抛 `ETyMaskError`(见 3.1)。 |
| `EditMask` | `string` | `''` | `Mask` 的别名(LCL / Delphi 用的名字),**同一个字段**,不参与流式化。名字一样不等于语言一样:`'!90:00;1;_'` 在 LCL 是一个合法的时间掩码,在这里一个槽位码都没有 —— 详见 3.1。 |
| `Text` | `TCaption` | `''` | 掩码后的显示串。**赋值会过掩码**,见 5.1。 |
| `IsComplete` | `function: Boolean` | — | 所有槽是否填满(可用于校验 / 门控 OK 按钮)。 |
| `ETyMaskError` | `class(Exception)` | — | 掩码不被接受时抛出。 |
| `TyMaskRejectReason` | `function(const AMask: string): string` | — | `''` = 可用;否则是拒绝原因。 |

另继承 [TTyEdit](edit.md) 的 `Alignment` / `OnChange` 等。

## 5. 行为

- **`UTF8KeyPress`**:提取当前有效字符 → 看下一个槽的类型 → 匹配则套用 `TyMaskApply` 重算 `Text`,否则吞掉。
- **`KeyDown` 退格 / Delete**:两个键同义(本模型没有"中间的洞"),删最后一个有效字符后重算 —— Delete 不会删掉掩码字面量。
- **粘贴(`FilterInsert`)**:与打字同一套判定,见 5.1。
- 纯函数 `TyMaskApply` / `TyMaskExtract` / `TyMaskNextSlot` / `TyMaskSlotAccepts` / `TyMaskIsComplete` / `TyMaskRejectReason` 承载全部逻辑,已单元测试。

### 5.1 `Text :=` / 粘贴:一套规则,只截断不补白

赋值和粘贴走**同一条判定**(所以 `Ed.Text := S` 和 Ctrl+V 同一个 `S` 不可能给出不同结果):把来的字符依次喂给下一个空槽,**合的留下、不合的丢掉**,字面量由掩码自己重建。

```pascal
D.Mask := '####-##-##';
D.Text := '2026/07/30';   // 斜杠不是掩码要的分隔符 -> 丢掉,数字入槽 -> '2026-07-30'
D.Text := 'hello world';  // 一个都不合 -> ''
D.Text := '123456789';    // 超出槽数的部分丢掉
```

**永不拒绝、永不抛异常** —— 这一点和 LCL 一致(`maskedit.pp:1656 ApplyMaskToText`,原注释就写着 "The text that is set, does not need to validate":它做的是补白和截断,不是校验)。**截断同 LCL,补白不同**:LCL 总是返回定长串、短了用空白字符补齐;本控件没有"空白字符"这个概念,`IsComplete` 是按填满几个槽定义的,所以短的就保持短,`IsComplete` 照实说 `False`。

已经合规的串(本控件自己的显示串、`.lfm` 里的值、从另一个掩码框复制过来的值)**原样保留**,`Ed.Text := Ed.Text` 是恒等。

> **注意(静态绑定):** `Text` 是属性覆盖,只拦通过 `TTyMaskEdit`(或其子类)类型引用的赋值。强转到基类 —— `TTyEdit(M).Text := X` —— 仍然会绕过掩码。别这么写。

## 7. 注意事项

- **追加式:** 从左往右录入,不支持在中间插入编辑(掩码字段常态);光标始终停在末尾。
- **换掩码清空:** 运行期设置新 `Mask` 会清空当前内容(掩码一般在使用前设定)。**流式化时例外**:`Text` 的 RTTI 槽位继承自 `TTyEdit`,写出时排在子类的 `Mask` **前面**,读回来时掩码还没生效;所以 `csLoading` 期间不清空,而是把已读进来的 `Text` 重新过一遍新掩码 —— 否则设计期填的值每次加载都会丢。
- **从 LCL / Delphi 移植:** 属性名 `EditMask` 能编译过,**不代表掩码串能照抄**。先读 3.1,把 `0 9 A a` 之类改写成 `#` `L` `C`,去掉 `;` 三段式。改漏了的两类会直接抛 `ETyMaskError`,其余(如混在槽位里的 `9`)按字面量处理。
- **校验:** `Text` 赋值和粘贴都过掩码,但"过了掩码"只保证**合规**,不保证**填满**;提交处仍应用 `IsComplete` 把关。
