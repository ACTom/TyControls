# TTyGrid 剩余功能 实施计划

> **执行方式**:逐项 TDD、逐项变异验证、逐项提交。每项完成后跑全量 + 重建示例。

**目标**:把 `2026-07-19-grid-parity.md` 里明确"未做/推迟"的条目一次做完,
让这个控件从"业务数据表格"补齐到"类电子表格"。

**顺序按"用户多快撞上"排**,不是按实现难度。

---

## P1 选区外框 + 填充柄

**为什么排第一**:用过 Excel 的人一分钟内就会去拖右下角;而且现在选区**连个边框都没有**,
只有一层底色。

- [x] 选区外框:活动选区矩形描一圈边。走主题 token `TyGridSelectionFrame`
      (base 层补进 `themes/light.tycss`,重跑两个生成器)。
- [x] 填充柄:选区右下角一个小方块。命中与绘制**同一个 FillHandleRect**。
- [x] 拖填充柄 → 把源区的值铺到拖出来的范围。
      语义:单格 = 复制;多格构成等差数列 = 外推;否则按源区**循环重复**。
- [x] `OnFillCells(Sender; const ASource, ATarget: TRect; var AHandled: Boolean)`
      让宿主接管(自定义序列)。
- [x] 填充走 `BeginUpdate/EndUpdate`。
- [x] **偏离**:只做纵向填充。横向拖柄在表格里少见得多,而半成品的可供性比没有更糟。
- [x] **偏离**:等差外推只认整数。浮点等差在表格里罕见,而误判的代价是把用户的数据算错 ——
      拿不准就退回"循环重复"。
- [x] 踩到的坑:柄与选区底色同为 accent → 画了等于没画;token 里加 `color:` 作描边色。
      柄探进正文窗格 1px,而光标停在固定行时那 1px 会被滚动平移 →
      chrome 必须裁到**它所属的窗格**(与行号、横格线同一类)。

**守卫**:拖出来的内容逐格断言(复制/外推/重复三种);柄的命中矩形与绘制矩形一致;
填充期间只重画一次。

## P2 行拖动(鼠标)

**为什么**:列能用鼠标拖、行不能 —— 不对称比缺失更扎眼。用户会去拖,然后什么都不发生。

- [x] 在**行头槽**里按下并越过阈值 = 拖行(与列头拖列对称)。
- [x] 走现成的 `MoveRow`(它已经会搬底色/行高/合并跨度)。
- [x] `OnRowMove(Sender; AFrom, ATo: Integer; var AAllow: Boolean)`。
- [x] 与行高分隔线手势的优先级:分隔线优先。
- [x] **新增约束(计划里没想到)**:排过序/分过组/藏过行时**拒绝拖行**。
      显示序不是数据序时,把行拖到某个屏幕位置没有意义 —— 松手排序就放回去了。
      与 `MergeSelection` 拒绝非数据连续的选区同一条道理。
- [ ] **偏离**:没画插入位置指示线。逐格拖动是**即时生效**的(每跨一行就搬一次),
      屏幕上直接看得到行在动,再画一条指示线反而是重复反馈。

**守卫**:阈值以内不触发;跨过阈值后 `MoveRow` 被调用且参数正确;
`AAllow := False` 能否决;分隔线区域不触发拖行。

## P3 撤销 / 重做

**为什么**:智能粘贴会自动扩表,删行不可逆。出错代价大。

- [x] 命令栈:`TTyGridUndoEntry` 只记逆操作所需的最小信息(哪一格、原值 / 原行数)。
- [x] 覆盖:**记录点收口在 `SetCells` + `SetRowCount` 两处**,于是改格值、粘贴、
      填充、增删行列、行移动全部自动被记下 —— 它们最终都经过这两个口子。
      这比"给每个功能各写一段记录"稳得多(后者正是本控件反复漏东西的方式)。
- [x] `Undo` / `Redo` / `CanUndo` / `CanRedo` / `ClearUndo` / `UndoLimit`(默认 100)。
- [x] Ctrl+Z / Ctrl+Y 走键盘。
- [x] 一次批量操作 = 一条记录:**事务边界直接复用 `BeginUpdate`/`EndUpdate`** ——
      值得"一次重画"的批量操作,正是值得"一次撤销"的操作。
      顺带把 InsertRow/DeleteRow/SwapRows/MoveRow/InsertColumn/DeleteColumn
      都包进了事务(它们本来就该批量重画)。
- [x] **偏离**:合并/取消合并暂未记录 —— 它们改的是格属性而不是 `Cells[]`,
      不经过收口点。要覆盖得再给属性存储加一个记录点,单独一步做更干净。
- [x] **偏离**:单条记录超过 20 万条目时**整条作废并清空栈**,而不是截断。
      半条撤销记录还原出来是一张四不像的表,比"这一步撤销不了"危险得多。

**守卫**:每种操作 undo 后**逐格**回到原状(不是只看行数);redo 再来一遍;
超过 UndoLimit 时最老的被丢弃;undo 期间不再往栈里压新记录(否则自我循环)。

## P3.5 物理排序模式(排序真的换数据,像 Excel)

**为什么**:这个控件反复出问题的那一族(合并吞行、合并块糊到别处、拖行没意义、
选区被拉长)根因都是**两个坐标空间且都是 Integer**,而不是"有间接层"本身。
Excel 没有这类 bug,因为它只有一个空间 —— 它排序是真把数据换位置的。

**Excel 的事实**:排序物理搬数据;**含大小不一的合并单元格时直接拒绝排序**。
也就是说我们给 `MergeSelection` 加的"数据行不连续就拒绝"与 Excel 是同一个答案,
不是绕开架构的权宜之计。Excel 敢物理改数据,前提是**它有撤销**。

- [x] `SortMode: (gsmDisplay, gsmData)`,默认 `gsmDisplay`(今天的行为,零回归)。
- [x] `gsmData` 且**没有筛选、没有分组、没有虚拟数据源**时:`SortByColumn` 真的置换
      存储(文字 + 逐格属性 + 行高 + 隐藏标记 + 合并跨度),然后 `FOrder` 重置成恒等。
- [x] 此后显示序 == 数据序,于是这几条"排序时拒绝"自动失效(不必再拒):
      `MergeSelection` 的数据连续性、行拖动的 `DisplayOrderIsDataOrder`。
- [x] 一挂上筛选/分组/虚拟源就自动退回 `gsmDisplay` 行为并恢复那些拒绝。
- [x] **必须在 P3 之后**:点一下列头就永久改写用户数据,没有 Ctrl+Z 兜底太凶险。
- [x] **实现上的关键选择**:"显示序是不是恒等"改成**看实际的序**(`FOrderIsIdentity`,
      在 `RebuildOrder` 里顺手算),而不是"有没有排序/分组/筛选"那种启发式判断。
      这比启发式**更准**(按一个本来就有序的列排,结果同样恒等,不该拒绝),
      而且物理排序之后必然恒等 —— 那几条限制**自动解除**,不必逐处去放行。

### 做 P3.5 时发现的相邻缺口(尚未修)
**排序不认虚拟数据源**:排序的比较读的是存储(`Cells`)而不是 `GetCellText`,
所以挂了 `OnGetCellText` 的表按任何列排,结果都是恒等序(存储全空 → 全部相等 →
稳定排序原样返回)。百万行虚拟表点列头**看起来毫无反应**,这是个真 bug。
连带后果:`CanSortPhysically` 里"虚拟源不物理排"那条守卫目前**无法被测试区分**
(排都排不动,搬什么都是搬了个寂寞)。守卫留着 —— 修好排序的那天它立刻变成必需的。

**守卫**:物理排序后逐格断言数据真的换了位置且 `FOrder` 是恒等;
逐格属性/行高/合并跨度跟着走;有筛选时**不**物理排序;虚拟源时**不**物理排序;
排序后合并与拖行不再被拒绝。

## P4 内嵌筛选行 + 条件组合

**为什么**:筛选下拉已经好用了,但"金额>1000 且 地区=华东"在 UI 上仍表达不了。

- [ ] 列头下面一条**筛选行**(自己一条带,不是数据行);每列一个输入框。
- [ ] 输入即筛(防抖),支持 `>100` `<=5` `<>x` `a..b` 这类前缀语法 ——
      走现成的 `SetColumnFilterEx` / `TTyGridFilterOp`,不自造第二套。
- [ ] `ShowFilterRow: Boolean`;高度进冻结带(与列头同族)。
- [ ] 多列之间 AND(与现状一致);同列多条件用 `;` 分隔走 OR。

**守卫**:筛选行不是数据行(命中/寻址/导出都不能把它算进去);
输入 `>100` 之后可见行数正确;清空恢复。

## P5 编辑器细节(M17 / M19)

- [x] 窄列编辑时编辑器**自动加宽**(`MinEditorWidth`,0 = 老行为)。不改列宽、不越右缘。
- [x] 下拉宽度可配(`TTyGridColumn.DropDownWidth`,0 = 跟列宽)。
- [x] `OnGetEditorProp` —— 拿到真正那个编辑器控件。
- [x] **偏离**:事件时机是"编辑器建好之后、交回调用方之前",不是"显示之前"。
      内建编辑器有十来种分支,各自 SetBounds/Visible/SetFocus 然后 Exit;
      逐个插事件正是本控件反复漏东西的方式。包一层 `DoBeginEdit` 统一发一次,
      收口一处、不可能漏 —— 代价是晚一步,而属性微调在这一步照样生效。
- [x] `MinEditorWidth` 默认 0(= 老行为)。默认改成非 0 会静悄悄改变每个既有工程的
      编辑手感,不值得。示例里显式打开做演示。

## P6 多级分组

- [x] `GroupByColumns(const ACols: array of Integer)`;分组行按层级缩进。
- [x] 小计按层级各算各的:一行算进它**所有祖先**组,于是每级小计各自成立。
- [x] 折叠状态按**层级路径**记(`Path`),不是按单个值。
- [x] 单列的 `GroupByColumn` 变成多列的退化情形 —— 只留一条实现,免得两套日后走样。
- [x] **测试数据的关键**:必须让**同名子组出现在不同父组下**(华东/北京 与 华北/北京)。
      第一版四个城市各不相同,于是"只比本级"和"折叠按单键记"两个变异都活了下来 ——
      那份数据对这两条守卫零分辨力。

## P7 版式持久化

- [x] `SaveLayoutToString` / `LoadLayoutFromString`:列宽/列序/可见性/排序键/冻结数。
      宿主自己决定存哪(注册表/ini/数据库都行)。
- [x] 版本号前缀,不认识的版本**什么都不做**并返回 False。
- [x] **读回来是"全有或全无"**:先把整串解析完并校验(列数、字段是不是数字、
      非负),全部合法了才动控件。半套版式(列宽还原了、列序没还原)比完全不还原
      更难排查。
- [x] **偏离**:不包含**行高**。行高可以有 RowCount 那么多条 —— 把百万行的表存成
      一个字符串不是"版式"而是数据。行高更贴近数据,宿主要存自己存。
- [x] **偏离**:不包含**筛选**。筛选是"我此刻想看什么",不是"我把表调成什么样";
      而且值集合可能很大。存版式时把用户的筛选一并复活,多半不是他要的。

**守卫**:改一通再 round-trip 回来,逐项断言一致;
残缺/被截断的字符串不能崩。

## P8 树形单元格

**排最后**:它其实是第二种形态,不是一个小特性。

- [ ] 某一列显示层级:缩进 + 展开三角 + 父子关系由宿主给
