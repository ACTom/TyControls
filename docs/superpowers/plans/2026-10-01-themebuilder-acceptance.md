# 主题编辑器验收

这是主题编辑器三期做完后的**一次性真机验收**入口：一张表列出三期所有要在真机上看的项，后面是等你拍板的决定、截图、发现问题怎么报。每项看完在「结果」列写 过 / 不过 / 现象。现在只有 1 期的项，2、3 期做完往下接着编。

## 这是什么，做了什么

`tools/themebuilder/` 下的桌面程序：左边写 `.tycss`，右边立刻看到控件换上这套主题的样子。主要给用 TyControls 的开发者给自己的程序做皮肤，也给我们维护 `themes/builtin/` 下的内置主题。3 期起可以接一个大模型，用一句话起草或修改主题。

- **1 期**：编辑与预览。左边是带 CSS 高亮、目录补全的编辑框，右边是按控件家族分八页的预览，停手约 0.3 秒就跟着变；预览有自己的样式控制器，写坏的主题只坏预览，工具界面不受影响；预览可切明暗、密度、全部禁用，对话框、弹出菜单、通知、真窗体也挂在预览的主题上。问题列表带行号、双击跳转，编辑器行号栏有标记、问题行有底色。新建（复制内置主题或极简模板）、打开、保存（换行符、BOM 原样）、最近文件；文件被外部程序改了会提示重新载入。编辑器配色跟随工具自己的皮肤（「视图 → 编辑器外观」）。中英双语。库里改了三处：设计期 StyleOverride 对话框里配好的编辑框拆成共用的 `TTyCssEditKit`、解析错误带上行列号、主题检查新增带位置和严重度的 `TyLintCssEx`（旧的 `TyLintCss` 输出逐字不变）。
- **2 期**：（待做）种子面板、Ctrl+点击跳到规则、覆盖检查、导出主题包、代码片段。
- **3 期**：（待做）AI。

分支 `feat/theme-builder`，1 期签收时头提交与全量测试条数见 1 期计划末尾的签收记录（`docs/superpowers/plans/2026-10-01-themebuilder-phase-1.md`）。

## 准备

- **编工具**：`lazbuild -B tools/themebuilder/themebuilder.lpi`，程序在 `tools/themebuilder/lib/<目标平台>/` 下（Windows 是 `tools/themebuilder/lib/x86_64-win64/themebuilder.exe`）。Linux 用 `--ws=gtk2` 或 `--ws=qt6` 编，macOS 用 `--ws=cocoa`。工具直接用库的源码编，不用先装 `tycontrols` 包。
- **设计期**（第 19 项）：先装 `tycontrols_dt.lpk` 重建 IDE。
- **配置文件**：设置、最近文件存在 `GetAppConfigDir(False)` 下的 `themebuilder.ini`——Windows 是 `%LOCALAPPDATA%\themebuilder\themebuilder.ini`，Linux 是 `~/.config/themebuilder/themebuilder.ini`，macOS 是 `~/.config/themebuilder/themebuilder.ini`。想从头来就删掉它。
- **顺序建议**：Win32 → Linux（GTK2、Qt6）→ macOS。表后的平台索引列了每台机器要做的项。

### 与规格不符、你可能想改的

- 侧栏只有「问题」一页（E1）；种子、AI 两页 2、3 期加。
- 预览换密度只换字号和内距，控件框的高度不变（E2）。
- 底层定义了的变量，用了也不报「未定义」（E3）。
- 编辑器不自动整理离开的那一行（E4）；设计期对话框照旧整理。
- 加载错误有的没有行号：`@import` 失败（库在加载时抛的，没有位置）和整份文档在当前模式下解析不出来的，排在问题列表最前面、行号处是「—」；值写错（如 `border-radius` 给三个数）检查会另报一条带行号的。
- 预览显示暗色时，一份只在亮色里定义了某个变量的文档会整个被拒（预览保持上一版），而不是先载入再在切暗色时拒绝——预览永远只显示它当前模式下能画出来的东西。
