# 主题编辑器验收

这是主题编辑器三期做完后的**一次性真机验收**入口：一张表列出三期所有要在真机上看的项，后面是等你拍板的决定、截图、发现问题怎么报。每项看完在「结果」列写 过 / 不过 / 现象。三期都做完了，表里是 1、2、3 期的全部项。

## 这是什么，做了什么

`tools/themebuilder/` 下的桌面程序：左边写 `.tycss`，右边立刻看到控件换上这套主题的样子。主要给用 TyControls 的开发者给自己的程序做皮肤，也给我们维护 `themes/builtin/` 下的内置主题。3 期起可以接一个大模型，用一句话起草或修改主题。

- **1 期**：编辑与预览。左边是带 CSS 高亮、目录补全的编辑框，右边是按控件家族分八页的预览，停手约 0.3 秒就跟着变；预览有自己的样式控制器，写坏的主题只坏预览，工具界面不受影响；预览可切明暗、密度、全部禁用，对话框、弹出菜单、通知、真窗体也挂在预览的主题上。问题列表带行号、双击跳转，编辑器行号栏有标记、问题行有底色。新建（复制内置主题或极简模板）、打开、保存（换行符、BOM 原样）、最近文件；文件被外部程序改了会提示重新载入。编辑器配色跟随工具自己的皮肤（「视图 → 编辑器外观」）。中英双语。库里改了三处：设计期 StyleOverride 对话框里配好的编辑框拆成共用的 `TTyCssEditKit`、解析错误带上行列号、主题检查新增带位置和严重度的 `TyLintCssEx`（旧的 `TyLintCss` 输出逐字不变）。
- **2 期**：种子与联动。侧栏第一页是「种子」：六个种子（`--accent`、`--surface`、`--on-surface`、`--border`、`--danger`、`--radius`）按明暗分两列，色块是文档在那种模式下实际算出来的颜色；改一个色块（或圆角的微调框），文本里只有那个值变、预览跟着变、Ctrl+Z 一次回去；值是表达式（`var()`、`darken()`……）或写在两种模式共用的 `:root` 里时先问一句；文档没写的种子灰着显示从底层继承的值，一改就在对应块里补一行；只有 `:root` 的单模式主题可以一键拆成明暗两套。预览里按住 Ctrl（macOS 上 Cmd）点一个控件，编辑器跳到它的规则，再点跳下一条，没有就在文末加一条空规则。「视图 → 覆盖检查…」列出主题写了、预览里没有的 typeKey（多半是拼错），和预览里有、主题和底层都没写的。「文件 → 导出主题包…」导出成文件夹或 zip，导出后用库自己的读取端读回、加载、逐模式试一遍，不过就什么都不留下。「文件 → 在程序里怎么用…」给出三种写法的代码片段，可复制。库这一期一个字节没改。
- **3 期**：AI。侧栏第三页「AI」：在「AI 设置」里配一个服务（OpenAI 兼容、Anthropic、本地 Ollama，五种预置帮你填地址和模型名；密钥 Windows 上用 DPAPI 加密、Linux / macOS 存在只有你能读的文件里；「测试连接」一句话说结果）；在 AI 页用一句话描述想要的主题，回答一段段流进输出框，随时可以停。结束后工具取出代码块、用和编辑器一样的标准检查（解析、未知属性、未定义变量、亮暗两种模式下预览画不画得出来），有错自动请模型改，最多两次。对比窗口左右并排、改动行着色、两边一起滚动，可以先在预览里试看；接受后编辑器换成新版本，Ctrl+Z 一次就能撤回，放弃什么都不变。同一份文档里记得之前的要求（「再暗一点」能接上），换文档重来。网络、密钥、限流、超时、格式不对都用一句话说清，密钥不出现在任何提示里。Windows 用系统的 WinHTTP，Linux / macOS 运行时加载系统的 libcurl，找不到只关掉 AI。另写了工具的使用文档 `docs/themebuilder.md` / `.en.md`。库一个字节没改。

分支 `feat/theme-builder`，1 期签收时头提交与全量测试条数见 1 期计划末尾的签收记录（`docs/superpowers/plans/2026-10-01-themebuilder-phase-1.md`）。2 期签收在 `8fb7e7d6`，全量 8770 / 0 / 0；期末两份审查之后的修复批另签收，全量 8801 / 0 / 0（两份签收记录都在 `docs/superpowers/plans/2026-10-01-themebuilder-phase-2.md` 末尾；修复批的真机项是第 48–52 项，并改了第 33、35、37、39、42 项）。3 期签收见 `docs/superpowers/plans/2026-10-01-themebuilder-phase-3.md` 末尾（全量 8934 / 0 / 0；WSL 里 libcurl 那条路两个库各 22 条全过）；3 期的真机项是第 53–72 项。3 期期末两份审查之后的修复批另签收（同一文件末尾「期末修复批签收」），它的真机项是第 73–76 项。

## 准备

- **编工具**：`lazbuild -B tools/themebuilder/themebuilder.lpi`，程序在 `tools/themebuilder/lib/<目标平台>/` 下（Windows 是 `tools/themebuilder/lib/x86_64-win64/themebuilder.exe`）。Linux 用 `--ws=gtk2` 或 `--ws=qt6` 编，macOS 用 `--ws=cocoa`。工具直接用库的源码编，不用先装 `tycontrols` 包。
- **设计期**（第 19 项）：先装 `tycontrols_dt.lpk` 重建 IDE。
- **配置文件**：设置、最近文件存在 `GetAppConfigDir(False)` 下的 `themebuilder.ini`——Windows 是 `%LOCALAPPDATA%\themebuilder\themebuilder.ini`，Linux 是 `~/.config/themebuilder/themebuilder.ini`，macOS 是 `~/.config/themebuilder/themebuilder.ini`。想从头来就删掉它。
- **AI 要一个服务**：一个 OpenAI / DeepSeek / Anthropic 的密钥，或者本机的 Ollama——装好后 `ollama pull qwen2.5-coder:7b`（或别的 7–8B 代码模型），**先设 `OLLAMA_CONTEXT_LENGTH=32768` 再启动** Ollama（默认的上下文太短，长请求的开头会被悄悄截掉）。测完从「AI 设置」里把密钥删掉。
- **Linux / macOS 的 libcurl**：`ldconfig -p | grep libcurl` 看有没有（Debian / Ubuntu 是 `libcurl4` 包）；macOS 自带。
- **AI 的配置**：在设置文件旁边的 `themebuilder-ai.ini`（Linux / macOS 另有存密钥的 `themebuilder-ai.keys`），想从头来就删掉。
- **顺序建议**：Win32 → Linux（GTK2、Qt6）→ macOS。表后的平台索引列了每台机器要做的项。

### 与规格不符、你可能想改的

- 侧栏只有「问题」一页（E1）；种子、AI 两页 2、3 期加。
- 预览换密度只换字号和内距，控件框的高度不变（E2）。
- 底层定义了的变量，用了也不报「未定义」（E3）。
- 编辑器不自动整理离开的那一行（E4）；设计期对话框照旧整理。
- 加载错误有的没有行号：`@import` 失败（库在加载时抛的，没有位置）和整份文档在当前模式下解析不出来的，排在问题列表最前面、行号处是「—」；值写错（如 `border-radius` 给三个数）检查会另报一条带行号的。
- 预览显示暗色时，一份只在亮色里定义了某个变量的文档会整个被拒（预览保持上一版），而不是先载入再在切暗色时拒绝——预览永远只显示它当前模式下能画出来的东西。
- 换密度也可能被拒（文档在那种密度下解析不出时），和切暗色被拒一样弹回并说明原因（第 25 项）。
- 只有一种模式的文档不显示为暗色：之前开着暗色，换成单模式文档后开关自动回到不勾，关窗口时存下的设置也不是暗色。
- 带 `@import` 的文档每次刷新慢一些（约 0.1–0.2 秒，E9）。
- 种子页的颜色不是预览算的，是一个不带密度包的独立模型按模式算的：预览在「现代」密度下，写在 `:root` 里的 `--radius` 被密度包换成 8，种子页仍显示文档写的值。
- 种子页在文档解析不了（或加载不了）时行都藏起来，只留一句「先修好问题列表里的错误」（期末修复：原来变灰时还显示着上一版的值）。
- 种子页藏着（侧栏在「问题」页或收起）时刷新不算种子页，切回来时才算（期末修复，为了打字时的刷新开销）；导入的文件在磁盘上改了而文档文本没变，种子页要等文本下次变了才看到。
- 圆角框连着的几下合成一步撤销，停手 0.25 秒才写回文本。
- 覆盖检查的「主题写了」只看当前文档自己的规则，`@import` 进来的文件里的规则不算（第一张单子可能多报）。
- 导出有文件夹、zip 两种，zip 只在主题不引用别的文件时能选（E11）；引用目录以外文件的主题导不出来（E12）。
- 3 期：校验比 spec 多一道「每个模式各试解析一次」（E31）。
- 3 期：精简参考不是构建时由脚本生成的文件，而是工具运行时从库的列表与内置默认主题拼出来的（来源仍是代码，手写的部分有片段守着）；实测约 4800 token，比 spec 估的 6–8 千少。
- 3 期：对比窗口也用 SynEdit（E35）。
- 3 期：OpenAI 兼容格式默认不发「最大输出」（E27）；「超时」是多久收不到数据，不是总时长（E28）。
- 3 期：发给模型的规则与参考是英文（E34）。
- 3 期：接受时只替换改了的那几行（仍是一步撤销），没变的行上的光标、书签不受打扰。
- 3 期：服务没按流式回答、而是一次给出整段 JSON 的，也接受。
- 3 期：AI 的输出框不折行（折行的输出框排 600 行要十几秒，不折行不到半秒）。
- 3 期期末修复：`http://` 发往别的电脑——不带密钥时只警告、照样能用（局域网里的 Ollama），带密钥一律不发；服务的重定向不跟（第 73、74 项）。
- 3 期期末修复：生成结束时有别的对话框开着，对比窗口不自动弹，要点「查看对比…」（第 76 项）；对比窗口左边是编辑器此刻的文本。
- 3 期期末修复：Linux / macOS 上正在解析主机名时点「停止」，要等解析完或 15 秒连接超时才生效（libcurl 的限制，写在使用文档「已知限制」里）。
