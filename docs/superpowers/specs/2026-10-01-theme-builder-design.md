# 主题编辑器（theme builder）设计

日期：2026-10-01　分支：`feat/theme-builder`（`D:/Projects/ty-3.1`）　状态：设计已定，待写第 1 期计划

## 1. 是什么，给谁用

`tools/themebuilder/` 下的一个桌面程序：左边写 `.tycss`，右边立刻看到控件换上这套主题的样子；可选接一个大模型，用一句话描述想要的主题，由它起草或修改。

- **主要用户**：用 TyControls 的开发者，给自己的程序做一套皮肤。要上手快、预览全、出错说得清、能导出成自己程序能加载的东西。
- **次要用户**：我们自己，维护 `themes/builtin/` 下的内置主题。能直接打开、保存仓库里的主题文件就够，生成脚本仍在工具外跑。

## 2. 已定的决定（2026-10-01 与用户逐条确认）

| # | 问题 | 定了什么 |
|---|---|---|
| 1 | 给谁用 | 两者都要，以开发者为主 |
| 2 | 编辑方式 | 文本 + 种子面板（6 个种子，双向同步）；不做全量变量表 |
| 3 | AI 接口 | OpenAI 兼容 + Anthropic 原生；本地模型（Ollama 等，`http://localhost`、无密钥）同样支持；默认流式 |
| 4 | AI 结果怎么落地 | 每次交回整份文件 → 我们解析 + lint → 有错回喂，最多 2 次 → 对比 → 用户接受才替换（可撤销） |
| 5 | 布局 | 用库里的侧栏工作台：侧栏放「种子 / 问题 / AI」三页，中间编辑，右边预览 |
| 6 | 预览 | 专门为检查主题做的预览页（按控件家族分页）；Ctrl+点击跳到规则；覆盖检查 |
| 7 | 交付 | 存 `.tycss`；导出主题包；给出「在程序里怎么用」的代码片段；不生成 Pascal 单元 |
| 8 | 平台与网络 | 编辑器三平台；AI 网络 Windows 用 WinHTTP，Linux / macOS 运行时加载系统 libcurl（找不到就只关 AI） |

第 8 条改了 2026-09-29 的初定（Linux 用 fphttpclient + 系统 OpenSSL）：FPC 3.2.2 的 OpenSSL 绑定只认到 1.1 的库名，发行版现在都是 3.x；libcurl 在桌面 Linux 上几乎都在、macOS 自带，FPC 有现成绑定，代理与证书走系统。

## 3. 不做的

- 不做停靠、不做多窗口（侧栏工作台就是布局）。
- 不做全量变量表（256 个变量），不给每个变量补类型和说明。
- 不生成 Pascal 单元；不在工具里跑 `gen-builtinthemes.ps1`。
- 预览不做「钉住悬停 / 按下状态」，这些状态靠鼠标去碰。
- AI 第一版不做「工具调用式」的小改动（改几个变量也整份重写）；用下来嫌慢再加。
- 不做成库的一部分：HTTP / 大模型客户端、编辑器都留在工具里，不对外承诺 API。

**要改的共享部分**（只有这三处，别的库文件不动）：

1. `designtime/tyControls.Design.Css.Editor.pas`：把「配好 CSS 高亮与目录补全的 SynEdit」拆成一个**不依赖 IDE 单元**的新单元（放在 `designtime/` 下，不引 `PropEdits` 之类），设计期的 StyleOverride 对话框和主题编辑器共用。对话框本身（原生 LCL 控件）留在设计期。
2. `source/tyControls.Css.Parser.pas`：`ETyCssError` 加 `Line`、`Col` 两个字段，抛错处填上；消息文字不变。
3. `source/tyControls.ThemeLint.pas`：新增带行号的 `TyLintCssEx`（每条问题带行号、严重度），旧的 `TyLintCss` 保持原样（它改为调用新函数再只取文字）。

`Base.pas`、`Painter.pas`、`StyleModel.pas`、`TextMenu.pas` 不改；执行中发现非改不可，停下来问用户。

## 5. 编辑、种子、预览、问题

### 5.1 数据流

- 编辑器文本停顿 300 ms → 解析 → 加载到预览控制器。解析失败时预览保留上一版能用的样子，问题列表标出错误。
- 种子面板改一个值 → 替换文本里那一行 → 同上。
- AI 结果接受 → 替换编辑器全文 → 同上。
- 每种来源的改动在编辑器里各算一步撤销。

### 5.2 种子面板

- 种子：`--accent`、`--surface`、`--on-surface`、`--border`、`--danger`、`--radius`（`themes/auto.tycss` 的 SEED 段）。
- 文件里有 `@mode light` / `@mode dark` 两块 → 面板分亮、暗两列；只有 `:root` 的单模式主题 → 一列，外加「拆成明暗两套」按钮（生成两个 `@mode` 块，暗色一列先用亮色的值）。
- 色块显示**解析后**的实际颜色（经预览控制器求值）。原值是表达式（`var()`、`darken()` 等）时格子标「表达式」，改之前确认一次，改后写成具体色值。
- 文件里没写的种子：灰着显示从底层继承的值，一改就在对应块里补上这一行。
- 只替换值，不动别的文本和注释；定位用容错的文本扫描（注释、字符串、嵌套块都要认得），不依赖解析器保留位置。

### 5.3 预览

- 预览区的控件挂**自己的** `TTyStyleController`，加载编辑器文本的方式和程序运行时加载主题相同（在底层之上叠加）。编辑器本身的界面用另一个控制器，写坏的主题只坏预览。
- 预览自带开关：明 / 暗、密度（经典 / 现代）、全部禁用。
- 分页（每页把一种控件的变体与状态并排）：基础、输入、列表与树、表格、容器与页签、菜单与工具栏、窗体外框、反馈。对话框、弹出菜单、真窗体（看标题栏按钮与阴影）用按钮弹出，弹出的窗口也挂预览控制器。
- `url()` 按文档所在目录解析；未保存的新文档找不到图片时，问题列表提示。
- **Ctrl+点击**：取被点控件的 typeKey 与变体，编辑器跳到那条规则（`urules.pas`）；没有就在文件末尾插入空规则，光标停在花括号里。
- **覆盖检查**：两张单子——文档写了规则、预览里没摆出来的 typeKey；预览里摆了、但文档与底层都没专门规则的 typeKey（提示「这些走的是默认样子」）。

### 5.4 问题列表

- 解析错误用 `ETyCssError.Line / Col`；lint 用 `TyLintCssEx` 的行号与严重度。
- 双击跳到行；编辑器行号栏标出有问题的行。
- 打开的文件被外部程序改了 → 提示是否重新载入（有未保存改动时提示会丢失）。

### 5.5 新建

- 复制任一内置主题的全文（文件头加注释「基于 xxx」）；或选极简模板：只有 6 个种子（明暗两套），其余全靠底层。

## 6. 保存、导出、界面

- `.tycss` 存 UTF-8，保持读入时的换行符；最近文件列表。
- 打开 `themes/builtin/*.tycss` 可直接保存；保存这类文件时状态栏提醒重跑 `gen-builtinthemes.ps1`。
- **导出主题包**：库里的 `ThemeBundle.pas` 只有读取端（目录源、zip 源、清单 JSON），打包在工具里写：tycss + 它 `url()` / `@import` 引用的文件 + 清单，格式以读取端为准。导出后用读取端（`TTyThemeZipSource`）读回并加载一遍，失败就报错、不留坏包。
- **代码片段小窗**：从文件加载、从主题包加载、把文本注册成命名主题——三种写法，可复制。
- 工具自己守示例硬规则：`.lfm` 窗体、真标题栏、运行时换肤；中英双语 `.po`，跟随系统语言。
- 编辑器外观（工具自己的主题）在「视图 → 编辑器外观」里选，和正在编辑的主题无关。SynEdit 是唯一的非 Ty 控件（库里没有代码编辑控件，设计期已有先例），它的颜色（底色、文字、选区、行号栏、高亮配色）取自编辑器外观的主题令牌，跟着换肤。
- 设置、最近文件、AI 配置存用户配置目录（`GetAppConfigDir`）。

## 7. AI

### 7.1 设置与密钥

- 多个配置，选一个当前用。每个配置：接口格式（OpenAI 兼容 / Anthropic）、服务地址、模型名、密钥（可空，本地模型不用）、最大输出长度、超时。
- 预置：OpenAI、DeepSeek、Anthropic、本地 Ollama、自定义（只是帮着填地址）。
- 「测试连接」：发一个最小请求，报成功或具体原因。
- 设置页写明：主题文本会发给你配置的服务。
- 密钥：Windows 用 DPAPI（`CryptProtectData`，当前用户范围）加密后存；Linux / macOS 存在权限 0600 的文件里。密钥不进任何日志、不进错误消息。
- 代理：WinHTTP 用系统代理设置（自动代理）；libcurl 读环境变量里的代理。

### 7.2 提示词

- 不发整份 `docs/tycss-reference*.md`（约 2 万 token，本地小模型装不下）。构建时由脚本从代码生成**精简参考**（约 6–8 千 token），编进工具：语法与限制（不支持的写法）、种子与推导变量、typeKey 清单（`Css.Catalog`）、属性与取值提示（`TyKnownStyleProps`、`TyStyleValueHints`）、一个完整的小例子。来源是代码，所以和引擎同步，不会因为文档没更新而过时。有守卫测试：生成物与源一致。
- 规则：只输出一个完整的 ```` ```tycss ```` 代码块；保持原有 `@mode` 结构；只用参考里列出的属性和 typeKey；优先改种子。
- 每次请求：精简参考（系统提示）+ 当前文档全文 + 用户的描述（+ 可选：当前问题列表）。
- 多轮：记住用户之前的描述（「再暗一点」能接上），但不重发旧的输出，只发最新文档，成本不随轮数滚大。

### 7.3 一次生成

1. 流式输出显示在 AI 页，随时「停止」。
2. 结束后取出代码块（没有代码块 = 失败，原文给用户看）。
3. 解析 + `TyLintCssEx`：解析错误、未知属性、未定义变量 → 把问题发回，让它改，最多 2 次；低对比度之类只提示，不算失败。
4. 两次后仍有问题 → 把结果和剩下的问题一起给用户，由用户决定。
5. 对比窗口（左右并排、改动行高亮）：可「在预览里试看」；「接受」替换编辑器全文（一步撤销）；「放弃」什么都不变。

### 7.4 出错

网络不通、401（密钥不对）、429（限流）、超时、应答格式不对：AI 页一句话说清原因，编辑器不受影响。libcurl 找不到：AI 页说明缺什么，其余功能照常。

## 8. 测试

- 共享改动：`ETyCssError.Line / Col` 对各类错误位置正确；`TyLintCssEx` 行号正确、旧 `TyLintCss` 输出不变；拆出的编辑器单元在设计期包里照常可用（编 `tycontrols_dt.lpk`）。
- 种子扫描：单 / 双模式、注释里的假种子、表达式值、缺种子插入、拆成两套；改动后其余字节不变。
- 规则定位：Ctrl+点击的查找 / 插入（变体、状态、注释、同名多条）。
- 预览：独立控制器——预览加载坏主题时编辑器界面的控件样式不变；覆盖检查的两张单子。
- 导出：打包后用 `TTyThemeZipSource` 读回并加载成功；缺文件时报错且不留文件。
- AI：两种接口格式的流式样本当夹具测解析（含分块到达、事件跨块）；测试里起一个本机小 HTTP 服务走真实传输（成功、断流、401、429、超时）；校验回喂流程用按脚本回答的假模型；精简参考生成物的守卫。
- 工具窗体：真建主窗体（照终端示例的做法），断言各页与侧栏建好。

## 9. 分期

和终端一样：每期整期写完，再一次编译、跑测试、集中变异、期末审查；三期都做完，用户一次性真机验收。

1. **编辑与预览**：拆共享编辑框；`ETyCssError` 行列号、`TyLintCssEx`；主窗体与侧栏工作台；预览各页（独立控制器、明暗 / 密度 / 全部禁用）；问题列表；新建（复制内置 / 极简模板）、打开、保存、最近文件；外部修改提醒；编辑器外观与 SynEdit 取色；中英 `.po`。
2. **种子与联动**：种子面板（双向同步、两列、拆成两套、表达式确认）；Ctrl+点击；覆盖检查；导出主题包（含读回验证）；代码片段小窗。
3. **AI**：传输层（WinHTTP、libcurl）；两种接口格式与流式解析；设置与密钥；精简参考生成器与守卫；生成—校验—回喂；对比与试看。

## 10. 风险

- **大模型输出质量**：靠我们的解析器 + lint 把关、有限回喂、最后由人确认；不指望一次对。
- **SynEdit 跟换肤**：只能改它暴露的颜色，边框、滚动条是原生的；可接受（设计期同样如此），在验收里看。
- **libcurl 的库名**：Linux 上可能是 `libcurl.so.4` 或 `libcurl-gnutls.so.4`，都试；macOS 是 `/usr/lib/libcurl.4.dylib`。
- **精简参考太长 / 太短**：生成器可调；以本地 8B 级模型能装下为下限，验收时用一个本地模型试。
